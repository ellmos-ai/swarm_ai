**Небольшой набор инструментов на Python для экспериментов с координацией нескольких LLM-агентов.** В него входят примеры параллельной обработки фрагментов, рабочих процессов с руководителем и исполнителями, стигмергии на SQLite, голосования большинством и маршрутизации к специалистам.

Состояние координации хранится локально. Вызовы Anthropic, Claude CLI или другого настроенного провайдера могут передавать промпты и данные запросов внешним сервисам. Перед использованием конфиденциальных входных данных ознакомьтесь с разделом [Поток данных и ограничения](SECURITY.md).

## Установка

```bash
git clone https://github.com/ellmos-ai/swarm_ai.git
cd swarm_ai
python -m venv .venv
```

Активируйте среду (`.venv\Scripts\Activate.ps1` в PowerShell или `source .venv/bin/activate` в Linux/macOS), затем установите проект:

```bash
python -m pip install -e .
swarm-consensus --help
```

Команда справки не отправляет API-запрос. Для интеграции с провайдером COMA установите проект с дополнительной группой зависимостей командой `python -m pip install -e ".[providers]"`.

## Первый запуск

Рабочий запуск консенсуса отправляет вопрос в настроенный API Anthropic и может повлечь расходы. Укажите `ANTHROPIC_API_KEY` и задайте оценочный предел затрат:

```bash
swarm-consensus --question "What is the capital of Australia?" --agents 3 --max-budget-usd 1
```

Этот предел задаёт положительную конечную оценочную границу инструмента; фактическое списание провайдера может отличаться. `--dry-run` оценивает запрос, не обращаясь к API.

## Инструменты CLI

- `swarm-consensus`: запрашивает ответы у независимых исполнителей и объединяет результаты.
- `swarm-benchmark`: сравнивает последовательные и параллельные запуски; запускается в пробном режиме.
- `swarm-translate`: переводит тексты, хранящиеся в настроенной базе данных SQLite.
- `swarm-summarize`: обобщает фрагменты, сохранённые в SQLite.
- `swarm-stigmergy-init`: создаёт локальную базу данных маркеров.

Параметры каждого инструмента доступны через `--help`. При реальном использовании провайдера для консенсуса, перевода и обобщения необходимо задавать положительные конечные оценочные пределы затрат. Для `ClaudeRunner` можно задать такой предел; в остальных сценариях работы с провайдерами нет единого общего предела.

## Ограничения во время выполнения

- `confidence` при консенсусе — это число голосов за победителя, делённое на общее число результатов исполнителей; в `agreement_ratio` учитываются только валидные ответы. Ни один из этих показателей не является калиброванной вероятностью, и совпадение ответов не подтверждает их фактическую правильность.
- Блокировки команды координируют сотрудничающие процессы с помощью атомарных захватов файла и отдельных отметок о присутствии каждого участника. Они не препятствуют записи со стороны процессов, игнорирующих или изменяющих протокол.
- Программа наследует переменные окружения и разрешения вызывающего процесса. `RunAsInvoker` не является песочницей операционной системы и не гарантирует запуск без повышения прав.
- Цели перевода `de`, `en`, `es`, `zh`, `ja` и `ru` — это языки выходных данных, а не шесть языков локализованного интерфейса. Справка CLI сочетает английский и немецкий; в экспериментальном графическом интерфейсе Tk подписи на немецком.
- Файл [`results/benchmark_20260306.json`](results/benchmark_20260306.json) содержит результаты одной исторической рабочей нагрузки. Эти измерения не позволяют судить об общей производительности.

## Связанные проекты

- [COMA](https://github.com/ellmos-ai/coma) — необязательный мост для интеграции с провайдерами через Spawner/adapter, который Swarm использует при установленной дополнительной группе зависимостей `providers`.
- [Roshambo](https://github.com/ellmos-ai/roshambo) — отдельный набор инструментов для координации независимо запущенных агентов с помощью сериализуемых аренд и памяти результатов.
- [MarbleRun](https://github.com/ellmos-ai/marblerun) — отдельный набор инструментов для настройки многоагентных цепочек.
